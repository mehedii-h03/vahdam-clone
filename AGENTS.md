# Development instructions

Before any implementation task, read `docs/PROJECT.md` first. It is the single
source of truth for scope, architecture, status, and the locked phase order.

After every completed task, update that document chronologically with changes,
routes, components, decisions, current status, validation, and the next task.

Follow the development rules in `README.md`. Do not advance implementation phases
without the corresponding user request. Run lint, typecheck, and build before
reporting an implementation task complete.
